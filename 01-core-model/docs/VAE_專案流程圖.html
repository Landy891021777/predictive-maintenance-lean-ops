VAE 預測性維護 — 完整資料流程圖

NASA CMAPSS 航太引擎感測資料　│　從資料集到成果，含每一步的「為什麼」

資料處理流程 VAE 模型核心 評估與成果 誠實註記 / 限制
1

資料載入　NASA CMAPSS FD001

train_FD001(20,631筆/100台引擎)、test_FD001、RUL_FD001。欄位=26：unit_number、time_cycles、setting_1~3、s_1~s_21。
為什麼：FD001 對應「高壓壓縮機(HPC)」單一故障模式，變因單純、適合驗證方法。每台引擎從健康跑到故障，是天然的退化資料。
2

資料健檢

檢查 shape、缺失值、describe 統計 → 結果：無缺失值；各感測器尺度差異大、非常態。
為什麼：進模型前的 sanity check。先確認資料乾淨，並發現「尺度不一」這個問題 → 決定後面要做標準化。
3

建立標籤　RUL（剩餘壽命）

RUL = 該引擎最大週期 − 當前週期
為什麼：原始資料沒有「還能撐多久」這個答案，必須自己算。用每台引擎自己的最大週期回推，得到每個時間點的剩餘壽命。
4

探索式分析 EDA

(a) 引擎壽命分佈（多數 190~210 週期故障）　(b) 相關係數熱圖　(c) 感測器 vs RUL 趨勢圖　(d) 箱型圖看分佈/離群。
為什麼：要先「認識資料」才能做對的特徵選擇。這步直接發現 s1,5,6,10,16,18,19 從頭到尾是常數。
5

特徵清理／選擇

剔除：7 個常數感測器 + index 欄 + 3 個 operating settings + RUL（當 y）。
為什麼：①常數感測器標準差≈0，對預測零貢獻、徒增維度雜訊；②index/settings 不是機況訊號；③只留真正反映引擎健康的感測器。
6

切分資料

train_test_split(X, y, test_size=0.3) → 訓練集 / 驗證集。
為什麼：留一部分驗證集評估泛化能力，避免只看訓練表現自我感覺良好。
誠實註記：測試集每台引擎只取「最後一個週期」（groupby.last()），因為 RUL_FD001 給的是每台引擎最後狀態的剩餘壽命。
7

標準化　MinMaxScaler

fit(訓練集) → transform(驗證/測試)，把所有感測器壓到 0~1。
為什麼：①感測器尺度差很大（如轉速 9000 vs 比值 0.03），不縮放會讓大數值主導；②神經網路在 0~1 範圍收斂更穩。
關鍵：scaler 只用訓練集 fit → 防止測試集資訊洩漏。
8

轉 Tensor + DataLoader

batch_size=32、shuffle=True。
為什麼：PyTorch 用張量運算；分批訓練省記憶體、梯度更穩；shuffle 打散順序，避免模型學到資料排列。
9

建構 VAE 模型　🧠 核心

Encoder：21 →(Linear+ReLU)→ 64 → 分岔成 μ(2維) 與 logvar(2維)
Reparameterize：z = μ + ε·σ　(ε ~ N(0,1))
Decoder：2 →(Linear+ReLU)→ 64 → 21（重建）
為什麼用 VAE：①非線性降維（贏 PCA）；②KL 讓潛在空間平滑可量距離（贏普通 AE）；③非監督、不需大量故障標籤（贏監督回歸）。
為什麼 latent=2：為了視覺化退化軌跡 + 可解釋；代價是資訊損失（準確率有上限）。
為什麼 reparameterize：讓「隨機抽樣」可做反向傳播（梯度能流過 μ、σ）。
10

損失函數

Loss = 重建誤差(MSE) + KL散度 × 0.0001
為什麼兩項：MSE 逼模型「還原得準」＝抓住真實訊號；KL 逼編碼分佈趨近 N(0,1)＝規範潛在空間、防止死背。
為什麼權重 0.0001：讓「重建準確」優先、KL 當輔助。權重太大→重建變差/退化；太小→失去規範化。
11

訓練

Adam(lr=0.001)、50 epochs。
為什麼：Adam 自適應學習率、收斂快又穩；50 epochs 讓 loss 收斂。
12

產生潛在表徵 (Embedding)

encode → 取 μ 當每台引擎的特徵向量。
為什麼用 μ 不用抽樣的 z：μ 是分佈中心，比隨機抽樣「穩定、可重現」，當特徵向量更可靠。
— 兩條應用分支 —
13A

視覺化退化軌跡

2D 散點，顏色 = RUL，畫出 健康(綠) → 故障(紅) 的退化路徑。
為什麼：證明 VAE「無監督」就自己學到退化方向，也方便對非技術者解釋。
13B

健康分類（最近鄰 / 少樣本）

support set = 訓練集 embedding，標籤由 RUL 分位數(0.33) 切「健康/危險」。測試點 → 找潛在空間最近範本 → 借標籤。
為什麼最近鄰：健康聚一團、退化離群，距離天然反映健康程度、省標籤。
誠實：門檻 0.33 是統計切法，非物理依據；更嚴謹可用 piecewise-linear RUL（上限約 125）。
14

模型評估

混淆矩陣 + Accuracy / Precision / Recall / F1 + 距離分佈圖。
為什麼看 Recall：漏報一台要壞的引擎（沒預警 → 空中故障）代價最高，所以重視「抓到要壞的比例」勝過單純準確率。
15

成果

✅ 實測：健康/故障在潛在空間清楚分離；分類指標（混淆矩陣）。
✅ 視覺：可解釋的退化軌跡圖。
推估（非實測）：「84% 成本↓ / 36% 故障風險↓」是用商業價值換算的估算，依賴與 baseline 的對照數字 → 面試務必說是「推估」，不可講成模型實測。
$

商業數字怎麼算的？（想像 100 個，一看就懂）

兩個數字的關鍵都一樣 —— 只看「壞的那部分」縮小了多少。
🟢 84% ＝ 省下的「無效維修」
來自 Precision 75% → 96%（喊你換的零件裡，幾個真的該換）

模型每喊 100 次「要換」：
• 舊：75 個該換，25 個白換
• 新：96 個該換，只剩 4 個白換

白換 25 → 4，浪費消掉 21/25 ≈ 84%。
🔴 36% ＝ 降低的「故障風險」
來自 Recall 70% → 81%（真的會壞的，幾台被提前抓到）

有 100 台快壞的引擎：
• 舊：抓到 70 台，漏掉 30 台
• 新：抓到 81 台，只漏 19 台

漏抓 30 → 19，風險消掉 11/30 ≈ 36%。
誠實講法：「假設 Precision、Recall 有這樣的提升，換算下來就是少 84% 無效維修、少 36% 故障風險。這組提升是跟一個 baseline 版本對照來的、非嚴格控制變因實驗，所以屬於合理推估。」

🧭 一句話串起整條邏輯

算出 RUL 標籤 → EDA 砍掉沒用的常數感測器 → 標準化 → 用 VAE 把 21 維壓成 2 維健康表徵 → 健康的聚一團、退化的離群 → 用距離判斷健康並畫出退化軌跡 → 用混淆矩陣評估、特別看 Recall。

📌 三個最常被追問的「為什麼」

Q：為什麼砍常數感測器？　標準差≈0、零資訊、徒增維度雜訊。
Q：為什麼 VAE 要 KL 散度？　規範潛在空間使其平滑，距離才能拿來判斷健康。
Q：為什麼 latent=2？　為可視化退化軌跡，是「可解釋性 vs 準確率」的取捨，非極限。
