# DMAIC 精實改善案：預測維護資料流程自動化

> **改善對象：** 客戶支援/維運團隊「設備健康資料處理與報表」的手動作業流程
> **方法論：** Lean Six Sigma — DMAIC
> **定調：** 本案主軸是**第二層流程浪費**（人工資料處理）；第一層實體浪費（設備停機）由 VAE 模型處理，於各階段標示為技術亮點。
>
> 🟢 = 可實測值　🟡 = 情境假設（可替換）　`(P2實測)` = 待 P2 VBA 階段以碼錶/程式計時填入

---

## D — Define（定義）

### 問題陳述
維運工程師每天需從 SAP 匯出設備感測/工單資料，手動在 Excel 清理與彙整，人工判讀健康狀態，再手動將報表以 Email 寄給相關人員。此流程**耗時、易錯、無法規模化**，且工程師的時間被行政作業佔用，無法投入更高價值的分析與改善。

### 專案範圍（SIPOC 摘要）
| 元素 | 內容 |
|------|------|
| **Supplier** | SAP 系統、機台感測器 |
| **Input** | 原始感測/工單匯出檔（CSV，含髒資料） |
| **Process** | 下載 → 清理 → 彙整 → 判讀 → 製表 → 寄送 |
| **Output** | 每日設備健康彙整報表 + 異常清單 |
| **Customer** | 維運主管、現場工程師、管理層（HK 分層） |

### 改善目標
1. 將每日手動資料處理工時降低 ≥ 80%（目標由 P6 ROI 表以實測驗證）。
2. 將「人工判讀」以 VAE 模型自動化，降低判讀主觀性與漏判。
3. 建立可持續監控的 Power BI HK 分層看板，異常自動通知。

### 對應 ASML JD
> *"use macro to replace manual download from SAP, manual summary in excel, manual sending reports by email"* — 本案 Define 的核心浪費即此句。

## A — Analyze（分析）

### 七大浪費（TIMWOODS）盤點——聚焦第二層流程浪費
| 浪費類型 | 在本流程的具體表現 | 根因 |
|----------|-------------------|------|
| **Motion（動作）** | 反覆手動下載、複製貼上、切換視窗 | 無自動化擷取 |
| **Waiting（等待）** | 等 SAP 匯出、等 Excel 手動彙整完成 | 序列式人工作業 |
| **Overprocessing（過度處理）** | 每天重複同樣清理步驟、格式化 | 無標準化巨集 |
| **Defects（缺陷）** | 髒資料人工修正錯誤、判讀主觀漏判 | 缺一致性規則與模型 |
| **Underutilized talent（人才未善用）** | 工程師時間耗在行政作業 | 未把重複工作交給自動化 |

### 根因結論
核心根因是「**重複性資料處理與判讀依賴人工**」。解法方向：
1. 標準化 + 自動化資料清理彙整（VBA）。
2. 自動化擷取與寄送（RPA / Power Automate）。
3. 判讀交給模型（VAE）。
4. 監控可視化（Power BI）。
